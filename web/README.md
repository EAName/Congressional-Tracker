# VA Tracker — web dashboard (Next.js on Vercel)

Interactive presentation layer for the tracker. The Python pipeline stays the
source of truth; this app renders the already-computed analysis from static JSON.

## Data flow

```
warehouse.duckdb ──▶ vact export-web ──▶ web/data/*.json ──▶ Next.js (this app) ──▶ Vercel
```

`web/data/{meta,scores,deviations,delegation}.json` are generated by the pipeline
and imported at build time — the app has no server data layer, so every page is
statically generated (fast, free, no database).

Regenerate the data after a warehouse refresh:

```bash
# from the repo root
vact export-web        # writes web/data/*.json
```

## Local development

```bash
cd web
npm install
npm run dev            # http://localhost:3000
```

## Deploy to Vercel

This app lives in the `web/` subdirectory of the repo, so tell Vercel that.

**Option A — dashboard (recommended):**
1. Import the Git repo at https://vercel.com/new
2. Set **Root Directory** to `web`
3. Framework preset auto-detects **Next.js**. Deploy.

Every push builds a Preview URL; merges to the default branch promote to
Production.

**Option B — CLI:**

```bash
cd web
npx vercel            # first run links the project; set root dir to "."
npx vercel --prod
```

## Keeping it current

The weekly refresh should run `vact export-web` and commit the updated
`web/data/*.json`; the push triggers a Vercel rebuild. (A later step can wire
this into the GitHub Actions publish job that replaced GitHub Pages.)
